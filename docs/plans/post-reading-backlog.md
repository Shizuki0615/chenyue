# 读书之后的待办（2026-10-26）

读书模块这一轮（设计稿还原 / 分组管理 / 美化 / 视觉精修）告一段落后，
记下的四项想法。这些不属于读书美化那批，是别的模块 / 全局交互。

> 这份清单在 2026-10-26 曾写过一个版本但没提交，被后续分支同步覆盖掉了。
> 现在按当时的四项标题重建，只保留方向，具体交互没定，动手前先和用户确认。

## 1. 音乐模块：歌词传情

方向：把当前播放的歌词接进聊天或互动里，让歌词本身成为表达的一部分。
待定：取哪一行歌词（当前句 / 用户选中的句子）、送到哪里（聊天草稿 / 卡片 / 定时触发）、
是否只对特定对象可见。

## 2. 聊天模块：提问卡片优化

方向：聊天里的提问卡片（ask 卡片）现在视觉与交互都还是最小可用，
需要优化卡片结构、选项排布和提交后的回显。
待定：卡片形态（单列 / 双列 / 折叠）、长选项怎么排、回答后是否留痕。

## 3. 全局路由：智能返回逻辑

方向：从二级页面返回时按来源判断，而不是一律回到上一层。
例如从聊天入口进读书、返回时应该回聊天而不是回桌面。
待定：来源栈怎么记（页面级 / 入口级）、跨应用跳转怎么处理、
直接从桌面图标进入时的默认返回目标。

## 4. 朋友圈：评论追踪逻辑

方向：朋友圈里评论的追踪与提醒，谁回了谁、未读怎么标。
待定：追踪粒度（整条动态 / 单条评论）、提醒形态（角标 / 条目 / 推送）、
自己评论被回复时是否单独提示。

---

## 5. 聊天问卡气泡化的遗留（2026-10-26）

第 2 项「提问卡片优化」进行中：问问他 / TA 问我（含单选、多选、文字）已经改成
左右气泡，选一个 / 好奇 / 吐槽 / 邀请同批接入。下面两项按用户 2026-10-26 的决定
先记在这里，暂不动：

- **批量问卷长卡（`special:'ask-survey'`）**：暂保持居中。它是 `chatAddSystem`
  塞进来的 `side:'in'`，但语义是「我发出的问卷」，直接按 side 排会跑到左边；
  而且它是多题长卡，套黑底气泡后选项 chip、答案、答题进度都要重新配色。
- **红包卡（`special:'redpacket'`）**：暂不动。红包有自己的红卡面、封面、
  领取/退回状态原地更新，和问卡的白色/黑色气泡不是一套；硬套容易做混。

等四个小卡真机确认后，再决定这两项要不要继续。
