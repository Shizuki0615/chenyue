# 一起读书

## 一句话

在一台设备上，和一个由本地规则驱动的联系人共读同一本书：你读你的，他读他的，批注在句子旁边相遇。

## 问题

现在的 App 里，所有「陪伴」都发生在聊天、卡片、游戏这些短时互动里。缺少一种可以持续几天、由内容本身承载的长期陪伴场景。读书天然具备三个特征：有进度、有情绪落点、有可回访的位置，很适合承载「他一直在」这件事。

同时现有技术形态是纯静态单机应用：GitHub Pages 只提供文件，没有后端、没有实时通道。这决定了「他」的一切行为必须在本地生成，不能假装有真实网络同步。

## 愿景

书架是书房，阅读器是安静的房间，批注是两个人留在同一句话旁边的小纸条。他不在聊天窗口里刷存在感，而是体现在「他也翻到了这一页」这种位置感上。

三条体验原则贯穿全部设计：

1. 读到才浮现。他的批注不预告、不集中展示，只有你真的读到那一句才出现。
2. 不比较。不显示百分比，不出现「快 / 慢」，不催促。位置只做陈述。
3. 不任务化。没有未读红点、没有打卡、没有推送。合上书就是结束。

## 非目标

第一版不做，且明确不做：

- 真实双人同步（需要后端、账号、鉴权、冲突合并，属独立项目）
- EPUB 解析
- 章尾感想
- 聊天里的共读邀请
- 阅读统计、书签、导出
- 同一本书与多人共读

## 角色与相关方

- 我：阅读者、批注作者、书架管理者
- 他：App 内既有联系人，行为由本地规则与文案池生成；位置、批注、回应都是本地状态
- 未来同步层：当前不存在，只在数据形状上预留

## 信息架构

桌面图标「一起读书」→ 书架 → 阅读器 → 句旁批注浮层。

书架是全局唯一的一份，不按联系人拆分；哪本书与谁共读，记在书的条目上（v1 只有一位联系人，字段先留好）。

桌面图标与聊天图标同级，支持拖动排序、改名、图标美化、字号跟随。角标只在他留下新批注或新回应时出现一个小圆点，不显示数字，进书即清。

聊天侧 v1 只提供「更多功能 → 一起读书」的直达入口，不做邀请。

## 阅读器

真分页，左右翻。顶部返回 + 书名 + 目录；底部页码与一条细进度条；正文区无常驻控件。

分页结果的缓存键是「章 + 视口尺寸 + 字号 + 行距」。任一变化才重算，否则复用。

单章超过约 5 万字时先切块再分页，避免一次布局过多节点。

## 位置的真值

他和我都只存两个数：第几章、章内第几个字。页码是按当前排版算出来的展示值。

判断「同页」不看页码数字，而是看他的偏移是否落在当前页覆盖的字符区间内。换字号、转屏、换机型都不会错位。

## 独立进度（底层前提）

我和他的进度始终是两份独立的真值，各自记「章 + 章内偏移」，任何时刻都不合并成一个进度字段，也不用我的进度覆盖他的。

- 跟随我：他跟着我推进。落后就追到我的位置；一旦超到我前面（例如刚从独立模式切回来），就停在原地等，不会把我拽到他那里
- 独立推进：他按自己的阅读速度往前读，允许明显超过我，也允许停在我后面；单次按离开时长补进度，设上限，避免隔夜一口气读完整本
- 今天不读：当天不推进，次日自动恢复原模式

由此得到两条展示硬规则：

- 他读得比我快时，写在我还没读到的那部分页里的批注不提前出现在正文，只有我翻到那一页才浮现
- 我给他的批注，只有他的位置越过那一句时才可能回应；未到之前一直安静留着

后续做「进度同步」和「他的批注」时，同步只能把两份真值分别对齐到各自的锚点，不能把两者绑成一个值。

## 「他在哪」

五种状态：未开始、共读中、停在这等你、读完了、今天不读。

呈现三处合一：

- 进度条上直径 18px 的头像刻度，描边 1.5px（浅色主题白、深色主题背景色）
- 进度条下方单行小字，左侧页码，右侧他的一句话，整行都是点击热区（高度不低于 44px）
- 点开从底部升起一张小卡：他的位置 +「这附近他留了 N 条批注」+ 一个主按钮

叠放规则：他在后侧、他在前侧（60% 不透明）、同页（贴末端外侧 6px，文案转主题色）。只有「不同页 → 同页」这一下做 180ms 位移，反向不回放动画。

防剧透硬规则：他在我前面时不提供跳转，只显示「他在前面，读到第 X 页」；他在我后面才允许跳。

文案池按状态分组轮换，24 小时内不重复，全部为陈述句。

## 批注

### 从选中到贴上

长按选句 → 浮条只有「批注 / 复制」→ 半框（最近 8 张字卡 + 搜索 + 自己写）→ 预览卡（原句 + 字卡全文）→ 贴上 → 句尾角标。

必须经过预览，不做点了就发。

### 锚点

每条批注只记：章、章内起止偏移、被选中原文快照、文字内容。不存页码、不存像素。

重新导入导致偏移变化时，用原文快照在该章内模糊匹配找回；找不到就进入这本书的「未定位批注」区，可见、可删，绝不静默丢弃。

### 一条批注

作者（我 / 他）、锚点、最终文本、来源字卡 id（仅溯源）、创建时间、回应指向、同步预留字段（版本号、设备标识）。

存文本快照而不是字卡引用：字卡库以后改版或删卡，历史批注不变样。

### 角标与浮层

我是实心点，他是空心圈；同句多条只显示一个角标加一个小数字（1 条不显示数字）。浮层按时间排列，回应缩进挂在被回应那条下面，一段最多 8 条，超出折叠。

### 他的批注怎么来

不预生成全书。按需生成：只有当我读到某一句、且他按当前模式也确实读到这一句时，才可能冒出来。生成后立刻落库，翻走再回来是同一条。

每章最多 3 条，两条间隔至少 8 句；候选句偏向有情绪或有画面的句子；文案优先从字卡库新增的「共读批注」类抽取，同一本书内不重复同一句。

### 他什么时候回应我

不是即时。我写下的批注进入待回应队列；只有下次打开这本书、且他的位置越过那句时，才可能回应。不给 100% 概率，允许一部分批注一直安静留着。每次打开最多回 2 条，按时间从旧到新。他未开始或停在这等你时，不回应。

### 硬规则

他的批注不可删除、不可编辑。自己的可长按编辑或删除，角标随之消失。单本上限 500 条，到上限只提示、不自动清理。不做未读红点体系。

## 导入与分章

入口只有两条：选 .txt 文件、粘贴文本。不做拖拽。

编码先按 UTF-8 解码；替换字符比例过高时提示「可能不是 UTF-8」，提供「按 GBK 重新解码」。国内 TXT 大量是 GBK，不做这步会被当成 App 坏了。

分章识别顺序：显式章节标题行 → 连续空行段落簇 → 每 8000 字硬切。导入后必须进入分章确认页，可改名、合并、拆分、手动插入分章点。前言、目录、作者的话归入「前言」章，任何文本不静默丢弃。

## 存储与容量

- 书架索引小，放本地存储一个键：书名、字数、章数、封面配色、最后打开时间、进度、共读状态、共读人
- 正文按章进数据库，一章一个键
- 批注按「书 + 章」一个键
- 三者都不整包读改写，写入前走现有闸门；失败必须有明确提示

容量：单本上限 3MB（约 150 万字），超出拒绝导入并说明；书架上限 20 本；书架页底部显示当前占用。

书籍正文不进云端备份与迁移包，只备份书架条目、进度、批注与回应。换机后重新导入原书，靠原文快照重新定位批注。

## 书架

封面用书名首字 + 由书名算出的稳定配色（8 套），不请求网络图片。按最后打开时间排序，最近在读置顶。封面底部一条细进度线，不显示百分比。长按：改名、删除；删除二次确认并明确告知正文与批注一起删除。

## 与现有系统的接入

- 桌面图标注册表：新增一项，纳入拖动、改名、美化、字号
- 字卡库：新增「共读批注」分类，内置预设 + 可增删改 + 受系统预设总档控制，必须懒加载
- 夜间免打扰：他的批注生成与「他在哪」的开口都走现有夜间开关
- 构建：新增 js 文件进构建清单；关键行为加哨兵，只增不删
- 不做系统推送

## 数据形状

同步预留集中在三个字段：author、rev、deviceId。当前单人单机只用本地值，将来接同步时不改语义。

书籍：id、标题、封面配色、章数、字数、导入时间、最后打开时间、共读人、共读状态、进度（章 + 偏移）。

章节正文：书 id、章序号、标题、正文。

批注：作者、章、起止偏移、原文快照、文本、来源字卡 id、创建时间、回应指向、rev、deviceId。

他的状态：模式（跟随 / 独立 / 今天不读）、章、偏移、更新时间。

## Intent Contract

intent: 在本地、无后端的前提下，为 App 增加可与联系人共读一本书的阅读空间（书架、真分页、字卡批注、他的位置与批注回应），并把数据形状做成将来接真实同步不需要重写的形态。

constraints:
- 不引入后端、不联网，「他」的一切行为由本地规则生成
- 不改动聊天、字卡库、桌面图标的既有行为，只新增接入点
- 书籍正文不进云端备份与迁移包
- 所有大键读写走现有闸门，禁止整包读改写，不静默丢数据
- 正文与批注按「书 + 章」分键；单本 3MB、书架 20 本
- 哨兵只新增不删名；新增 js 文件必须在构建清单登记

success_criteria:
- 导入约 2MB 的 TXT，可自动分章，并能在确认页改名、合并、拆分
- 改字号后进度不错位（存字符偏移而非页码）
- 选中一句可用字卡或自由文字批注，角标落在句尾
- 他的批注只在我读到的句子浮现，翻走再回来是同一条
- 「他在哪」五种状态正确，他在我前面时不给跳转
- 强刷、杀进程、切后台后，书架、进度、批注不丢

risk_level: medium

## Verification Contract

verify_steps:
- run build: `node build.mjs`，要求打回体检通过、哨兵全绿
- run check: `node tools/verify-worktree-revert.mjs`
- check 存储: 导入 3MB 边界书、超限书、GBK 书各一次，确认提示明确且不静默失败
- check 分页: 改字号 / 转屏 / 切深浅色后重开，进度落在同一句
- check 批注: 写、编辑、删除、他的角标浮现、回应延迟与上限
- check 备份: 导出备份包，确认不含正文且批注进度完整
- confirm 真机: OPPO / Android 16 上完成一次完整走查（导入 → 读 → 批注 → 关后台 → 重开）
- confirm 回退: 摘掉桌面图标入口后，既有功能与数据不受影响

## Governance Contract

approval_gates:
- 本设计定稿
- 分章确认页的真机手感
- 批注贴合与选句浮条的真机手感
- 上线前真机全量走查

rollback: 功能是独立模块与独立存储键，下线只需摘掉桌面图标入口，不迁移、不改动任何既有键。

ownership: 用户负责产品验收，Agent 负责实现与自测。

## 阶段拆分

### v1（本设计覆盖：读 + 批注 + 他在哪）

1. 导入与分章（含编码探测、分章确认页）
2. 书架与存储（索引、封面、上限、崩溃后不丢）
3. 阅读器与真分页（缓存、性能、改字号重排）
4. 选中与批注（浮条、字卡选择器、预览、锚点、角标、浮层、编辑删除）
5. 他的位置（五种状态、进度条刻度、文案池、防剧透）
6. 他的批注与回应（按需生成、待回应队列、上限、夜间静默）
7. 桌面图标接入与角标
8. 备份范围调整与哨兵登记

### v2

1. 章尾感想（写完后是否同步到聊天待定）
2. 聊天里的共读邀请（沿用现有邀请的概率与同意/拒绝）
3. EPUB 解析
4. 书签与阅读统计（若确有需求）

## 风险与开放问题

风险：
- Android WebView 的长按选区行为差异大，可能触发系统菜单而非自定义浮条，需要真机验证，必要时自定义选句层
- 超长章节若无分页缓存，改字号时明显卡顿
- 重新导入同一本书会导致锚点漂移，快照匹配在极端情况下仍可能失败，届时出现「未定位批注」
- 字卡库体量已大，新增分类若未懒加载会拖慢字卡库首屏
- 只支持用户自带文本，不内置任何受版权保护的书

开放问题：
- 章尾感想写完后要不要同时发到聊天
- 共读邀请被拒后隔多久可以再问
- 要不要书签，还是只靠进度
- 多联系人时同一本书能否改绑共读人

## 创意收集（2026-10-24，待挑选）

定位：纯前端本地规则，不联网、不新增后端；只复用两份进度、批注锚点与时间戳、翻页节奏、当前时间。
以下均为候选，尚未排期，等 UI 视觉精修后再开工。

1. 折角书签：他先走，但书签一直夹在你这页
触发：独立推进下他的进度领先你一章或 800 字以上，你打开这本书。
效果：他在哪小卡的圆点先停在远处，一秒后滑回你当前页边缘，停 1.2 秒再回位。你若在这页停留 30 秒没翻，浮一句「我先往前走了几步，在这儿等你」。
频控：每次打开最多一次，每天最多两次。
不触发：跟随模式下他本来就停下等你；「今天不读」当天不触发。
落地：低。

2. 铅笔记号：他读过的地方，纸上有痕迹
触发：你翻到的页里有句子已在他的进度之前。
效果：句边出现极淡的铅笔竖线或小点，不显示文字；点一下才提示「他读过这里」。只在你已读到的范围内显形，不提前露内容。
落地：低。

3. 双圈批注：你们停在了同一句
触发：你写下批注时，同章同句已有一条他的批注（用现有句子切分判定，字符区间重叠过六成即算同一句）。
效果：角标从单圈变双圈；点开是两张并排的纸条，他的在上。每本书首次触发时他那张末尾临时多一句「我们居然停在同一句」，之后双圈保留但不再加句。
不触发：他超前时这条尚未到可见区间，双圈先不画，等你读到他的纸条再补上。
落地：中。

4. 封存一句：他折了一句，等你读到才给看
触发：他独立推进时每天最多一条，只挑「他自己读过、你还没读到」的句子。
效果：书架一张共读手账「他今天折了一句，等你读到第 X 章」，只给章序号不给内容。你读过那句，它变成句边普通纸条，末尾多一行「你终于读到这了」。七天未解锁文案改「他还在等」，十四天收回；每本同时最多三条。
落地：中。

5. 深夜留灯
触发：22:00 后你还在读，且他处于「读过 / 在读」；每夜一次。
效果：阅读器角落两盏小灯，他那盏轻亮。23:30 你还没合书，页脚浮一张纸条「灯我留着，明天再读也一样」，点掉即消失。
落地：低。

6. 翻页被看见：他记得你读得快还是慢
触发：同一页停留超过 90 秒，或 10 秒内连翻 5 页；每章各最多一次。
效果：章末感想出现「这页你停了很久」或「你翻得好快，是不是在找我？」。前者他追着在那页留更长的纸条；后者他把下一张纸条藏到章尾。
落地：低。

7. 错过七天：他写下，又划掉了
触发：他某条批注超过 7 天你才读到。
效果：纸条变成「他 7 天前写下这句，后来划掉了」，下面留被划掉的淡字（可点开看），再下一行才是现在的句子。点开旧句有概率回「你看到这个了？」。
落地：中。

8. 此刻同读
触发：你与他的最近阅读时间落在同一个 10 分钟窗口内（他的「在读」由独立推进时间推出来）。
效果：他在哪小卡头像浮一圈轻呼吸光，页脚显示「此刻 · 同读」。连续同读 15 分钟后翻到下一章，他留一句「这一章我们一起翻过去的」。累计到一定次数，书脊上多一道细纹。
落地：低到中。

推荐第一批：1 + 3 + 4。三者都只用现有数据，一个给即时反馈、一个给默契、一个给长期悬念。
实现顺序建议 3 → 1 → 4：先写稳「同一句」的判定，另外两个都简单。
